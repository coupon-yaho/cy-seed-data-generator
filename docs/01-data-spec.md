# 데이터 사양

무엇이 얼마나 만들어지는가.
모든 숫자는 `seedgen/config.py` 상수에서 파생되므로 `--scale`을 바꿔도 비율은 유지된다.

기준 문서는 프로젝트의 `ERD.sql`이다.
`PRD.md`, `ERD.md`, `seed.yaml`과 어긋나는 지점이 여러 곳 있어 ERD.sql을 최상위 권위로 뒀고,
결정 내역은 내부 문서에 있다.

## 회차 구성

```
[과거 회차 144개]  12 브랜드 × 12개월
  └─ 회차당 재고 18,000 ~ 34,000장, 총재고 약 393만
  └─ 발급 300만 건 분배 → 평균 소진율 79%
  └─ 회차별 소진율 60~100% 흩뿌림 (완판 25% · 미달 75%)
  └─ 전부 CLOSED

[현재 회차 3개]  재고 100%, 아직 발급 0건
  #1 모카빈     재고 10,000  전체 공개   ← 부하테스트 기준 시나리오
  #2 필름아레나 재고  3,000  GOLD↑
  #3 딜리버리고 재고  2,000  전체 공개
  open_at = 시드 실행 시각 + 5분, status = SCHEDULED
```

총재고를 발급 수보다 크게 잡은 이유가 있다.
재고와 이력이 같으면 모든 회차가 완판되어 검증 배치의 "잔여재고 > 0" 분기가
한 번도 실행되지 않는다.

현재 회차만 상대 시각인 것도 마찬가지다.
절대 시각을 박으면 그 시점이 지난 뒤 오픈런을 재현할 수 없다.
시드를 재실행하면 `SCHEDULED`로 리셋되어 반복 재현이 되고,
검증의 결정론은 `verify(as_of)`가 담당하므로 이게 결정론을 깨지는 않는다.

## 분포

### 회원 등급 (100만)

| 등급 | 비중 | 인원 | 참여 가능 회차 |
|---|---|---|---|
| VIP | 5% | 50,000 | 12개 브랜드 전체 |
| GOLD | 15% | 150,000 | 11개 (헬스클럽 제외) |
| SILVER | 30% | 300,000 | 9개 |
| WELCOME | 50% | 500,000 | 8개 (전체 공개만) |

유저 활동은 파레토로 편중시킨다. 상위 30만 명이 이력의 80%인 240만 건을 갖는다.
인당 8건이면 144개 회차 중 8개에 참여한 셈이라 자연스럽다.

### 발급 상태 (300만)

| 상태 | 목표 | 실제 |
|---|---|---|
| ISSUED | 40% | 1,200,000 |
| USED | 35% | 1,050,000 |
| EXPIRED | 15% | 450,000 |
| CANCELLED | 10% | 300,000 |

오차 0으로 맞춘다. 방법은 [분포 설계](02-distribution-design.md)에 있다.

### 하위 변형

| 항목 | 비율 | 결과 |
|---|---|---|
| USED 중 사용→취소→재사용 이력 보유 | 20% | 210,000. `issuance_usages` 2행이고 1행은 취소됨 |
| ISSUED 중 USED 에서 복원된 건 | 5% | 60,000. `issuance_usages` 1행이고 취소됨 |
| 24시간 내 만료 | 1% | 최근 회차의 `valid_days` 를 맞춰서 생성 |
| `issued_grade` ≠ 현재 등급 | 등급 제한 회차의 3% | 발급 후 강등 시뮬레이션 |
| `phone_hash` 중복 | 0.5% | 전화번호는 UNIQUE 가 아니라는 설계를 데이터로 표현 |

### 시간축 기울기

상태 분포를 균일 적용하면 1년 전 회차에 `ISSUED` 120만 건이 남는 부자연스러운 데이터가 된다.

| 회차 시기 | 상태 경향 |
|---|---|
| 최근 1~2개월 | `ISSUED` 우세 (만료 임박 1%가 여기 집중) |
| 3~6개월 전 | `USED` 우세 |
| 7~12개월 전 | `EXPIRED` 우세 |

시간축으로 기울여도 전역 합계는 위 표 그대로 유지된다.

## 이력 534만이 나오는 산식

발급 1건마다 최소 1행(ISSUE), 최대 5행이 쌓인다.

```
ISSUED    1,200,000 × [ISSUE]                                = 1,200,000
  └ 5% 60,000 은 USED 에서 복원  → [+USE, +CANCEL_USE]          +120,000
USED      1,050,000 × [ISSUE, USE]                           = 2,100,000
  └ 20% 210,000 은 사용→취소→재사용 → [+CANCEL_USE, +USE]       +420,000
CANCELLED   300,000 × [ISSUE, CANCEL]                        =   600,000
EXPIRED     450,000 × [ISSUE, EXPIRE]                        =   900,000
                                                        합계  ≈ 5,340,000
```

전이는 합법 경로만 생성한다. `USED → EXPIRED`는 만들지 않는다.

```
ISSUE       (없음)  → ISSUED
USE         ISSUED  → USED
CANCEL_USE  USED    → ISSUED      역방향 허용 (주문 취소)
CANCEL      ISSUED  → CANCELLED   종단
EXPIRE      ISSUED  → EXPIRED     종단
```
